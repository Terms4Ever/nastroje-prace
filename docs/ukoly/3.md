# Úkol 3: Zavedení pracovního projektu

## Zadání

Zajistit pravidla správného založení a napojení nového osobního pracovního Gitu.
Vlastník vybral připnutou kopii kontrol bez dalšího tokenu. Následně požadoval
sjednocení složky hooky, odznaků a rozcestníku dokumentace. Zveřejnění centrální
sady je pouze předmětem posouzení; viditelnost zůstává privátní. Úkol nemá Mantis.

## Změna

PHP project-init exportuje čistý konkrétní commit do prázdné samostatné složky.
Lock zaznamenává původ i otisky a spouštěče ověřují vlastní kopii. Šablony a
pravidla pokrývají převzetí SVN, GitHub metadata, první issue, dokumentaci,
skutečné testy, hooky, CI, chráněné main, čistý clone a vědomou aktualizaci.
Project-check kontroluje napojení, volitelně i vzdálené nastavení a důkazy.
Nové osobní soubory jsou výslovně vyloučené ze SVN balíčků.

README má jeden odkaz na složku záznamů, stejné odznaky PHP a licence jako
společné nástroje a pravdivě uvedenou závislost. Hooky se instalují jen místně
do hooky; globální konfigurace ani původní nastroje se nemění.

## Ověření

Pozitivní i negativní scénáře zakládají pouze dočasné Git kopie. Testují
skutečný hook, první commit s issue číslo 7, nový clone, výpočet aplikace,
poškozenou kopii, ztracený lock, cizí hooky a chybné nastavení GitHubu.
README projde i s 500 záznamy bez jejich vyjmenování. Výsledky přesného commitu
se dokládají lokálním check a Windows/Linux CI; SVN běží povinně v Linux CI.

Posouzení zveřejnění zahrnuje dostupnou Git historii, issues, komentáře,
metadata a protokoly Actions. Zjištěny jsou pracovní názvy v dokumentaci a
historii; kontrola vzorů přihlášení není absolutním důkazem nepřítomnosti tajemství.
Podrobné zjištění zůstává v místním předávacím dokumentu mimo verzovaný repozitář.

## Předání

Změna je určená pro privátní nastroje-prace a pro ověření jeho nové verze.
Skutečné aplikační repozitáře ani firemní SVN se tímto úkolem nezakládají ani
nemění. Zapojení konkrétní aplikace vyžaduje její vlastní vstupy a splněný postup.
